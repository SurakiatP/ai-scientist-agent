## เป้าหมายและขอบเขต

ออกแบบประสบการณ์เว็บ AI Scientist สำหรับนักวิจัย NECTEC ตั้งแต่หน้าแนะนำผลิตภัณฑ์ไปจนถึงพื้นที่ทำงานวิจัย โดยใช้แบรนด์ AI Scientist ของตนเอง ผู้ใช้ต้องเห็นว่าแอปช่วยเปลี่ยนโจทย์วิจัยเป็นแผน หลักฐาน การวิเคราะห์ และรายงานได้อย่างไร พร้อมแยกข้อเท็จจริงที่ตรวจสอบแล้วออกจากผลที่ AI สรุป เป้าหมายรอบนี้คือ **ภาพ UI และเอกสารส่งต่อให้ Claude Code** ไม่มีการแก้โค้ดหรือรับรองว่าความสามารถใน TOR ใช้งานได้แล้ว

ข้อมูลใน TOR เป็นแหล่งความต้องการของโครงการ ไม่ใช่คำสั่งให้แก้โค้ดหรือข้ออ้างด้านผลิตภัณฑ์ หน้าแนะนำต้องไม่ใช้คำกล่าวอ้างเรื่องความแม่นยำ ประสิทธิภาพ ลูกค้า หรือการรับรองจาก NECTEC ที่ยังไม่มีหลักฐาน

## ทิศทางภาพ: Evidence Field Notebook

ขยายโลกภาพที่โปรเจกต์ใช้อยู่: กระดาษอุ่น พื้นที่อ่านสบาย ตัวอักษรไทยชัด และเส้นคั่นบาง ๆ ให้ดูเหมือนสมุดงานวิจัยที่จัดระเบียบดี สีเขียวเฟิร์นบอกการกระทำหลัก สีเขียวอมฟ้าบอกหลักฐานและการตรวจสอบ สีอำพันบอกสิ่งที่ต้องทบทวน ใช้สีเท่าที่มีหน้าที่จริง ไม่มีภาพสมองเรืองแสง วงโคจรนีออน การ์ดไล่สี หรือข้อความการตลาดที่เกินหลักฐาน

หน้า landing มีจังหวะและภาพถ่าย/ภาพประกอบเชิงบรรณาธิการที่เป็นธรรมชาติขึ้น แต่ยังใช้ตัวอักษร สี และรายละเอียดเดียวกับ workspace ภายใน เพื่อให้การกด “เริ่มต้นใช้งาน” รู้สึกต่อเนื่อง ไม่ใช้ตราหรือสีทางการของ NECTEC

**ข้อเสนอของผู้ออกแบบ:** ยึดระบบสีและตัวอักษรปัจจุบันใน `DESIGN.md` เป็นฐาน แล้วขยายเป็น dark theme ที่ออกแบบจริง ไม่กลับสีแบบอัตโนมัติ ผู้ใช้ยังไม่ได้ยืนยันเฉดสีหรือภาพ hero ขั้นสุดท้าย

## เส้นทางผู้ใช้และหน้าจอ

1. **Landing page — ก่อนเข้าสู่ระบบ:** แถบนำทางเรียบง่าย ชื่อ AI Scientist, สลับภาษา/ธีม, hero ที่บอกว่าเริ่มจากคำถามวิจัยและตามรอยหลักฐานได้, ปุ่ม “เริ่มต้นใช้งาน”, ภาพตัวอย่างการเดินทางจากโจทย์ → แผน → หลักฐาน → ผลวิเคราะห์ → รายงาน, ส่วนอธิบายขอบเขตและข้อจำกัดอย่างตรงไปตรงมา ไม่มีฟอร์มสมัครหรือ login หากระบบปัจจุบันยังไม่มี
2. **Research home — หลังเริ่มต้น:** รายการงานวิจัยล่าสุดและสถานะ, ช่องเริ่มโจทย์ใหม่ที่เด่นที่สุด, ทางลัดกลับงานค้าง, ภาพรวมหลักฐาน/รายงานของแต่ละงานแบบย่อ หน้าแรกไม่ควรเป็นแชตเปล่า
3. **Research question & plan:** ช่องโจทย์ไทยหรืออังกฤษ, โครงร่างแผนที่แก้ไขได้ก่อนเริ่ม, ขั้นตอนและสถานะขณะ Hermes ประมวลผล, ปุ่มหยุด/ลองใหม่/ดำเนินต่อ, ขอบเขตของคำถามและสิ่งที่ยังไม่ทราบ
4. **Evidence & source library:** ค้นและกรองแหล่งข้อมูล, แถวเอกสารที่สแกนได้เร็ว, ชื่อ/ปี/ผู้แต่ง/แหล่ง/DOI หรือ PMID เมื่อมี, สถานะตรวจสอบตัวระบุ, แผงรายละเอียดพร้อมข้อความหรือโน้ตที่เชื่อมกลับโจทย์; แยก “พบเอกสาร” จาก “สนับสนุนข้อสรุป”
5. **Analysis workspace:** ชุดข้อมูลและไฟล์ที่ใช้, ขั้นตอนการวิเคราะห์ Python, ผลลัพธ์ตาราง/กราฟ, log ข้อผิดพลาดที่อ่านได้, provenance ว่าผลใดมาจากข้อมูลและรันใด ไม่แสดงผลสมมติเป็นผลจริง
6. **Report editor/export:** โครงรายงานที่เรียบเรียงจากงานในโปรเจกต์, อ้างอิงกลับไปยังหลักฐานและผลวิเคราะห์, ตรวจส่วนที่ยังขาด, คำสั่งส่งออก PDF/DOCX เมื่อ backend รองรับ
7. **Settings:** ภาษา ไทย/English, รูปลักษณ์ Light/Dark/System, ค่าการทำงานที่ผู้ใช้ต้องจัดการจริงเท่านั้น; การกำหนดโมเดล/API แสดงตามความสามารถจริงและไม่เผย secret ในภาพ

นำรูปแบบ component ของ Open Notebook ที่เหมาะกับงานวิจัยมาใช้ใหม่: shell กับ sidebar, notebook/project list, source list, detail panel, settings, state chips และเนื้อหาแบบ split view แต่จัดลำดับตามงาน AI Scientist; หน้า podcast/transformation ของต้นทางไม่กลายเป็นเมนูหลักโดยอัตโนมัติ

## องค์ประกอบและพฤติกรรมร่วม

- Navigation: บน desktop ใช้ sidebar ขนาดพออ่านชื่อเมนูและสถานะงาน; บนมือถือใช้เมนูเปิดปิดได้ ไม่บีบเนื้อหาวิจัยเป็นสามคอลัมน์
- Work header: breadcrumb, ชื่องาน, สถานะ, การกระทำหลักหนึ่งอย่างต่อบริบท
- Evidence row: metadata ครบในระดับที่ข้อมูลมีจริง, badge ระดับตรวจสอบ, action เปิดรายละเอียด/ผูกกับข้อสรุป
- Plan step: ชื่อขั้นตอน, สิ่งที่จะทำ, สถานะ waiting/running/done/needs review/error, control ที่ใช้ได้ตามสถานะ
- Inspector: แผงข้างสำหรับที่มา รายละเอียด และประวัติการเปลี่ยนแปลง; บนจอเล็กเปิดเป็นแผงเต็มจอ
- Empty/loading/error: อธิบายสิ่งที่เกิดขึ้นและทางไปต่อด้วยข้อความเฉพาะงาน ไม่ใช้ skeleton หรือปุ่มไร้หน้าที่เป็นคำตอบสุดท้าย

## ระบบธีมและภาษา

- Light เป็นพื้นกระดาษอุ่น; Dark เป็นพื้นถ่านอมเขียวและแผ่นงานที่แยกชั้นด้วยเส้น/ค่าความสว่างอย่างพอดี; System ตาม OS และอัปเดตเมื่อ OS เปลี่ยน
- Semantic colors ต้องรักษาความหมายเดิมทั้งสองธีม: primary action, verified evidence, review needed, error และ disabled; กราฟไม่ใช้สีเพียงอย่างเดียวแยกชุดข้อมูล
- ภาษาไทย/อังกฤษเปลี่ยนข้อความทุกส่วนของ UI รวมถึงสถานะ ข้อผิดพลาด ปุ่ม และข้อความในภาพตัวอย่าง; คงคำวิชาการ/DOI/PMID ตามมาตรฐาน
- ความยาวข้อความไทยและอังกฤษต่างกัน: ปุ่มและ navigation รองรับการขยาย, ตารางมีทางอ่านบนมือถือ, วันที่/เลขมีรูปแบบเหมาะภาษา
- คอนทราสต์ข้อความตาม WCAG AA, focus ชัด, ใช้แป้นพิมพ์ได้, ขนาดเป้าสัมผัสเหมาะสม, เคารพ reduced motion

## ขอบเขตระบบและการส่งต่อ

Hermes เป็น backend ตามการตัดสินใจของผู้ใช้; เอกสารนี้ไม่กำหนด API contract, ไม่ถือว่า Hermes มีฟีเจอร์ TOR ครบ และไม่สั่งให้ Claude Code เปลี่ยน backend โดยพลการ ภาพ UI จะใช้ข้อมูลจำลองที่ติดป้ายชัดในเอกสารส่งต่อ Claude Code ต้องจับคู่แต่ละ component กับข้อมูล/สถานะจริงก่อนเปิดใช้

ชุด mockup ที่จะสร้างหลังอนุมัติ: `01-landing-light`, `02-research-home-light`, `03-question-plan-light`, `04-evidence-light`, `05-analysis-light`, `06-report-light`, `07-evidence-dark`, `08-mobile-landing`, `09-mobile-evidence`, `10-settings-light`, `11-landing-english` ภาพ `04`, `07` และ `09` ใช้งานและข้อมูลชุดเดียวกันในสถานะ “พบเอกสารแล้ว มีรายการหนึ่งรอตรวจสอบ DOI” เพื่อเปรียบเทียบ Light/Dark และการยุบ inspector บนมือถืออย่างตรงไปตรงมา ภาพ `10` ทำให้ตัวเลือกภาษาและธีมชัดเจน ส่วนภาพ `11` ตรวจการขยายตัวของภาษาอังกฤษ ภาพเป็นตัวอย่างองค์ประกอบและลำดับชั้น ไม่ใช่แหล่งข้อความหรือ pixel specification ที่แม่นยำ ต้องมีคำอธิบายทุกภาพและรายการ component/states ส่งต่อใน Markdown

## สิ่งที่ยังเป็นข้อเสนอ

เส้นทางหน้าและชื่อเมนูข้างต้นเป็นข้อเสนอด้าน UX; รายละเอียดข้อมูลและการทำงานต้องตรวจจากโค้ดและ backend ตอน Claude Code ลงมือ ภาพ hero, microcopy และตำแหน่ง responsive จะตัดสินจาก mockup หลังอนุมัติทิศทางนี้
